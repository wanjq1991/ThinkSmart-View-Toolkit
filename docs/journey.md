# 折腾全程：一台 Teams 会议屏变成学习终端的 6 天

这份文档按时间顺序记录整个过程，重点不是"做了什么"，而是**每一步卡在哪、怎么判断出来的**。
具体的命令和原理在 `flashing-guide.md`、`tweaks.md`、`desktop.md` 里，这里只留主干。

---

## 总览

| 阶段 | 目标 | 卡住的点 | 结论 |
|---|---|---|---|
| 1. 摸底 | 搞清楚这台机器是什么 | 无电池、无电源键、2GB 内存、锁 bootloader | 硬件限制先列清单，能省掉后面一半弯路 |
| 2. 解锁 | 解 bootloader 签名校验 | 官方不提供解锁 | EDL 刷 userdebug `aboot` |
| 3. 备份 | 刷坏了能回滚 | 12 个分区、3.8GB 存储 | EDL 全分区 dump，这步没跳过 |
| 4. 刷机 | LineageOS 15.1 + GApps + root | `addonsu` 让 init 卡在 logo | 换 Magisk，`boot_patch.sh` 命令行修补 |
| 5. 系统层 | 让设备真的能用 | 时间、内存、唤醒、横屏、壁纸、全屏 | 六个独立问题，逐个实测 |
| 6. 桌面层 | 变成学习终端 | 重启按钮、第三方桌面方向、抢桌面、诗句排期 | 四个问题，见 `desktop.md` |
| 7. 整理 | 把过程变成可复现的仓库 | —— | 就是你现在看的这个 |

## 阶段 1-4：把系统跑起来（10/31）

这部分已经写进 **[flashing-guide.md](flashing-guide.md)**（1100+ 行，含每个报错的对照表），
不再重复。只留三个当时判断错、后来纠正的点：

**① `addonsu` 不能用。** 这版 LineageOS 的 sepolicy 里没有 `u:r:su:s0` 域，
刷进去 `superuser.rc` 会让 init 在 LENOVO logo 处死循环。
判断方法：`adb logcat -b all` 完全没输出，但 `fastboot`/`recovery` 正常 —— 说明是 init 阶段挂的，
不是系统崩了。救回来不用重刷，挂载 `/system` 删掉四个文件即可。

**② Magisk 应用内修补会失败。** 这版 boot image 的 ramdisk 格式和 Magisk 应用里的解包逻辑对不上。
改用 `boot_patch.sh` 命令行，把 `boot.img` 和 `Magisk-v26.4.apk` 一起喂进去，一次成功。

**③ 别用电脑 USB 口供电。** 这台机器没有电池，USB 数据口只有 500mA。
表现为随机黑屏（背光灭但系统活着）、触摸失灵、莫名重启。换 5V/2A 电源适配器后全部消失。
**这条比任何软件优化都有用**，但当时花了半天在软件层找原因。

## 阶段 5：系统层的六个坑（10/31 – 11/1）

| 问题 | 表面现象 | 真正原因 | 文档 |
|---|---|---|---|
| 时间永远不对 | 重启回到 1970 | 无 RTC + 运营商拦 UDP 123 | [tweaks §2](tweaks.md) |
| 内存长期 96% | 频繁 OOM 杀后台 | zram 只给了 509MB | [tweaks §1](tweaks.md) |
| 熄屏后叫不醒 | 按音量键没反应 | 距离传感器误报遮挡，`KEYCODE_WAKEUP` 被防误触分支拦掉 | [tweaks §3](tweaks.md) |
| 桌面不横屏 | 设置能横屏、桌面锁竖屏 | 密度 260 算出 492dp < 600dp，被判成手机 | [tweaks §4](tweaks.md) |
| 换不了壁纸 | `cmd wallpaper` 没有实现 | Android 8.1 没这个 shell 命令，只能写文件 + 重启 | [tweaks §5](tweaks.md) |
| 状态栏碍眼 | 占两行画面 | `policy_control immersive.full=*`，但首次会弹教学框 | [tweaks §6](tweaks.md) |

这六个问题有一个共同点：**表面现象指向的层，和真正出问题的层，永远不是同一层。**
`tweaks.md` 开头那张"按层往下切"的表就是从这里总结出来的。

## 阶段 6：桌面层（11/4）

原计划是"装个桌面 App 就完事"，实际花了整整一天，因为每一步都会冒出一个新问题。

### 6.1 重启按钮点不动

第一反应是"权限问题"，加了一堆权限，没用。
真实情况是三层全断：钥匙（`api_key`）没配、门（`127.0.0.1:8767`）没开、执行的人（FreeKiosk）没装。

**教训**：一个功能有三个前置条件时，先把三个都验证一遍，不要按顺序修第一个。
`cat /proc/net/tcp` 看端口、`ls shared_prefs` 看配置、`pm list packages` 看依赖 —— 三条命令两分钟。

### 6.2 Aerial 方向反了

以为是"应用不支持横屏"。实际是 `landscape`(rotation 1) 和这块面板的正向(rotation 3) 差 180°。

没有源码，改二进制清单。第一次改错了偏移（把元素 chunk 起点当成了扩展头起点），
改完装不上，报 `No value supplied for <android:name>` —— 说明 XML 结构被改坏了。

**教训**：`screencap` 的截图方向跟着显示旋转走，倒 180° 的截图在电脑上看是正的。
验证方向只能读 `dumpsys display` 的 `mOverrideDisplayInfo`。

### 6.3 装完就抢桌面

改掉 `HOME` category 重启，还是被抢。

`adb logcat -b all | grep orchard` 才看到 `guard.BootReceiver` 在 `LOCKED_BOOT_COMPLETED`
阶段就起来了 —— 这个阶段比"解析默认桌面"早得多，`HOME` category 根本管不到。

**教训**：`HOME` category 决定"能不能当桌面"，`BOOT_COMPLETED` 决定"开机谁在前台"，
这是两件事，要分别处理。

### 6.4 诗句排期

需求变了两轮：先要 365 条一天一条，再要手动切换、且切换要影响第二天。

第一版用 `dayOfYear % 365`，手动切换后第二天会跳回日历算出来的那条，不符合需求。
改成锚点法（记"哪天切到了第几条"），跨天逻辑不用单独写，是算法的自然结果。

**踩到的实现坑**：Java 的 `%` 对负数返回负数，往回翻几条就崩。必须 `Math.floorMod`。

### 6.5 点击区域

第一版"上一条"热区给了整个控件的 40%，用户反馈"太大了，只要句首一小块"。
改成按前 8 个字的实际测量宽度算，并加上下限 160px / 上限 40% 的双向夹取。

**教训**：这类"手感"参数没法一次写对，必须让用户在实际屏幕上试。

## 如果重来一次

按重要性排序，这些能省掉最多时间：

1. **先确认供电。** 5V/2A 插墙，不要用电脑 USB。这一条能消掉一半"玄学故障"。
2. **刷之前做 EDL 全分区备份。** 12 个分区，出任何事都能回滚，成本 20 分钟。
3. **先查层，再改代码。** 按 `tweaks.md` 那张表从上往下切，不要从最熟悉的层开始猜。
4. **验证要回读状态。** `input keyevent` 返回 0 不代表屏幕亮了，`su -c reboot` 返回 0 不代表重启了。
5. **改二进制先打偏移草稿。** AXML 的 element/chunk/attribute 三层偏移差一个字节就全错。
6. **手感参数留给真机调。** 点击热区、震动、动画时长，模拟器上定不下来。
